# AionUi-zhlx 二开计划：渐进式 AI 决策支持工作台（v3）

## Context

基于 AionUi（21k+ star 的开源多 Agent 协作桌面应用）进行二开，构建面向内部团队的 **AI 决策支持工作台**。核心目标：让用户将一个模糊问题，经过四阶段推进（问题定义 → 调研发散 → 方案评估 → 决策收敛），最终输出可解释的决策建议，并沉淀全过程数据。

v3 基于 Codex Review（架构/数据层）和 Gemini Review（前端层）修订。

---

## 关键架构决策

### 决策 1：Conversation 与 Stage 的映射 — 一阶段一 Conversation

AionUi 不支持运行时切换 Assistant。每个阶段需要不同的 Assistant，因此为每个阶段创建独立 Conversation。

```
DecisionSession (1)
  ├── StageRun: problem_definition → conversationId_1 (绑定 问题定义助手)
  ├── StageRun: research            → conversationId_2 (绑定 调研分析助手)
  ├── StageRun: comparison          → conversationId_3 (绑定 方案评估助手)
  └── StageRun: convergence         → conversationId_4 (绑定 决策收敛助手)
```

- `conversationId` 放在 `stage_runs` 表上
- SessionPage 切换阶段 = 切换显示的 conversation（用 display:none 隐藏非活跃阶段，保留滚动位置和草稿）

### 决策 2：MCP Server 是必做项

AI 自由文本 → 结构化数据库记录的唯一可靠路径是 MCP 工具调用。

```
用户输入 → AI Assistant 分析 → 调用 MCP 工具
  → DecisionMcpServer 写入数据库
  → ipcBridge.decision.dataChanged.emit()
  → Renderer SWR mutate() → 右侧面板实时更新（带 Highlight 动画）
```

### 决策 3：阶段状态机 — 支持回退和跳过

```
problem_definition ←→ research ←→ comparison ←→ convergence

每个阶段的状态：pending | active | completed | skipped

合法转换：
  - 前进：当前 completed/skipped → 下一阶段 active
  - 回退：任意已完成阶段可重新 active（创建新 StageRun，保留旧快照）
  - 跳过：当前 active → skipped → 下一阶段 active
```

### 决策 4：阶段完成标准（自动判定 + 用户确认）

| 阶段 | 自动判定条件 | 用户动作 |
|------|------------|---------|
| 问题定义 | output 中包含非空 needBrief | 点击"确认需求简报" |
| 调研发散 | ≥1 ResearchItem 且 ≥1 CandidateOption | 点击"完成调研" |
| 方案评估 | ≥2 CandidateOption 有 scores | 点击"完成评估" |
| 决策收敛 | 存在 DecisionRecommendation | 点击"确认决策" |

自动判定提供视觉提示（按钮高亮），最终推进由用户主动触发。

### 决策 5：前端路由 — 子路由模式（仅改 Router.tsx 1 行）

**不在 Router.tsx 平铺 5 条路由**，改为：

```tsx
// Router.tsx 中仅新增 1 行
<Route path='/decision/*' element={withRouteFallback(DecisionLayout)} />
```

在 `src/renderer/pages/decision/index.tsx` 内部定义子路由：

```tsx
// decision/index.tsx
<Routes>
  <Route index element={<WorkbenchPage />} />
  <Route path='session/:id' element={<SessionPage />} />
  <Route path='research/:id' element={<ResearchPage />} />
  <Route path='result/:id' element={<ResultPage />} />
  <Route path='admin' element={<AdminPage />} />
</Routes>
```

**Router.tsx 冲突风险从"中偏高"降至"低"。**

### 决策 6：消息组件切换 — 缓存不销毁

切换阶段时，不销毁消息组件，用 `display: none` 隐藏：

```tsx
// StageInteraction.tsx
{stages.map(stage => (
  <div key={stage} style={{ display: stage === currentStage ? 'block' : 'none' }}>
    <MessageContainer conversationId={stageConversationMap[stage]} />
  </div>
))}
```

保留滚动位置、输入草稿、加载状态。避免闪烁和重复请求。

### 决策 7：MCP 上下文分层 — 摘要 + 详情

避免 Token 爆炸：

| 工具 | 返回内容 |
|------|---------|
| `decision_get_context_summary` | 每阶段产出物的摘要（≤500 token） |
| `decision_get_context_detail` | 指定阶段的完整数据（按需查询） |
| `decision_get_research_item` | 单个调研条目详情 |

AI 默认拿摘要，需要深入时按需查询详情。

### 核心前端设计

#### SessionPage 三栏布局

```
┌──────────┬─────────────────────────────┬────────────────┐
│ Stage    │  StageInteraction           │ ContextPanel   │
│ Nav      │  (缓存式消息区)              │ (结构化数据)    │
│          │                             │                │
│ ● 问题定义│  复用 MessageContainer      │ 需求简报       │
│ ○ 调研   │  display:none 切换          │ 调研卡片       │
│ ○ 评估   │  保留滚动位置+草稿           │ 对比矩阵       │
│ ○ 收敛   │                             │ 决策建议       │
│          ├─────────────────────────────┤                │
│          │ StageCompleteBar            │                │
│          │ [回退] [跳过] [推进到下一阶段]│                │
└──────────┴─────────────────────────────┴────────────────┘
```

- 使用 CSS Grid：`grid-template-columns: 200px 1fr 350px`
- 右侧面板支持拖拽调整宽度
- **响应式**：宽度 < 1024px 时，右侧面板切换为从右侧滑出的 Drawer

#### DecisionUIContext — 瞬时 UI 状态

```typescript
type DecisionUIState = {
  // 三栏布局
  rightPanelCollapsed: boolean;
  rightPanelWidth: number;
  // 选中状态
  selectedResearchItemId: string | null;
  selectedCandidateId: string | null;
  // 编辑状态
  editingDimensionId: string | null;
  // 阶段切换
  currentStage: DecisionStage;
  // 新数据高亮
  highlightedItemIds: Set<string>;
};
```

#### 消息组件复用策略

1. 从 `src/renderer/pages/conversation/` 提取 **`MessageContainer`** 纯组件（MessageList + InputArea，不含全局副作用）
2. 在 `StageInteraction` 中为每个阶段渲染一个 MessageContainer
3. 用 `display: none` 隐藏非活跃阶段，不销毁
4. 每个 MessageContainer 独立管理自己的 SWR 缓存

#### 实时更新 + 动画

```
MCP 写入 → dataChanged 事件 → useDecisionDataSync
  → SWR mutate() → 右侧面板更新
  → 新增项 ID 加入 highlightedItemIds → CSS highlight 动画
  → 2 秒后自动移除高亮
```

#### 性能策略

- 路由级：React.lazy 懒加载 5 个页面
- 数据级：按当前 Stage 动态请求，不一次性加载所有阶段数据
- 消息级：MessageContainer 内部分页加载
- 交互级：阶段推进用**乐观更新**，立即刷新 UI

#### 响应式适配

| 屏幕宽度 | 布局方式 |
|----------|---------|
| ≥ 1280px | 三栏并排 |
| 1024-1280px | 右侧面板可收起，默认收起 |
| < 1024px | Tab 切换（进度/对话/数据）或右侧面板为 Drawer |

## Phase 5：端到端集成 [串行，4 个子阶段]

### 5a. 阶段创建与 Conversation 绑定

- `createSession()` 自动创建第一个 StageRun + Conversation（绑定问题定义助手）
- `advanceStage()` 自动创建下一阶段的 Conversation + 注入前序上下文摘要
- SessionPage 根据 currentStage 显示对应消息流

**验证**：创建 Session → 问题定义对话 → 推进 → 自动创建调研对话并切换

### 5b. MCP 到 UI 实时联动

- `useDecisionDataSync` 监听 `dataChanged` 事件
- SWR mutate 刷新数据 → 右侧面板更新 → 新增项 Highlight 动画

**验证**：AI 调用 `add_research_item` → 右侧 1-2 秒内出现新卡片（带高亮）

### 5c. 阶段流转 UI 交互

- StageCompleteBar 实时检测完成条件
- 推进：乐观更新 UI → 调用 advanceStage → 中间区切换 Conversation
- 回退：确认框 → revertStage → 旧快照可查看
- 跳过：确认框 → skipStage

**验证**：条件满足后按钮高亮 → 推进/回退/跳过全链路正常

### 5d. 错误处理与边界

- MCP 工具参数非法 → 返回错误描述，AI 自动重试
- 阶段推进失败（条件不满足）→ UI 提示缺少什么
- Conversation 创建失败 → 回滚 StageRun
- MCP 连接断开 → 重连机制 + UI Loading/断开状态提示
- 网络断开时禁止对话输入，显示断开提示

**验证**：非法参数 → AI 重试；断开连接 → UI 正确提示

## 前端规范（遵循 AionUi 现有模式）

- 组件：`@arco-design/web-react`，不用原生 `<button>/<input>/<select>`
- 图标：`@icon-park/react`
- 样式：UnoCSS 工具类优先，复杂样式用 CSS Modules
- 颜色：语义化 token（`uno.config.ts` / CSS 变量），不硬编码
- IPC：严格走 `ipcBridge.xxx.method.invoke()`
- 数据获取：SWR
- 路径别名：`@renderer/*`、`@process/*`、`@common/*`
- TypeScript：strict mode，不用 any
- 命名：组件 PascalCase，hooks useXxx，工具 camelCase
